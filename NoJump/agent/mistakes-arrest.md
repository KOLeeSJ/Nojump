# Mistakes Arrest
 
이 문서는 과거의 실수를 기록하고 동일한 문제의 재발을 방지하기 위한 가이드라인입니다.
 
## 재발 방지 프로토콜 (Trigger & Arrest)
 
### 1. 경로 및 스펙 불일치
- **Trigger**: 404 에러, API 경로 불일치, 또는 "문서와 코드가 다르다"는 피드백 발생 시.
- **Arrest**: 
    1. 기준 문서(`architecture/specs/` 등)를 먼저 확인합니다.
    2. 컨트롤러 -> 설계 문서 -> 관련 설정 순서로 동기화합니다.
    3. 수정 후 반드시 해당 엔드포인트를 직접 테스트(curl 등)하여 검증합니다.
 
### 2. 출력 및 보고 누락
- **Trigger**: 상세한 디프(diff)나 로그를 요청받았으나 요약만 전달한 경우.
- **Rule**: 요청받은 원본 데이터(코드, 로그)를 먼저 제공한 후, 요약이나 분석은 그 뒤에 덧붙입니다.
 
### 3. 도구 사용 및 규정 준수
- **Trigger**: 특정 도구 사용을 지시받았으나 임의로 다른 방법을 선택하여 실패한 경우.
- **Arrest**: 지시된 도구를 우선적으로 사용합니다. 도구 사용이 불가능할 경우 즉시 보고하고 대안을 논의합니다.

## 인시던트 로그 (Incident Log Template)
 
새로운 실수가 발생하면 아래 양식에 맞춰 기록하고, 다음 세션에서 이를 숙지하도록 합니다.
 
### ## Incident (YYYY-MM-DD) - [제목]
- **Mistake (원인)**: 무엇이 문제였는지, 왜 발생했는지 기술.
- **Symptom (현상)**: 어떤 에러 메시지나 부작용이 나타났는지 기술.
- **Detection (탐지)**: 어떻게 문제를 발견했는지 기술.
- **Arrest (해결/방지)**: 어떻게 해결했으며, 앞으로 어떻게 예방할 것인지 기술.
