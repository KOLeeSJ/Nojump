## Phase 1 — Core Loop Prototype (Active)

### In Scope (반드시 구현)
1. **점프 키 무력화 약속** — 점프 키는 입력을 받고(애니메이션·시그널) 결과는 없다. (GDD §2.1) — ✅ `Player.gd:_register_jump_input`
2. **좌우 이동 + 중력 + 낙하** — Godot `CharacterBody2D` 기반. — ✅ `Player.gd`
3. **사망 → 즉시 재시작 루프** — 사망 페널티 없음. (ROADMAP Phase 1)
4. **테스트용 단일 스테이지** — 첫 트릭이 발현될 수 있는 *절벽 + 너머 발판* 구조. (GDD §3.4 트릭 카탈로그 확정 후보)
5. **첫 트릭 구현** — "절벽 앞에서 위쪽 응시 → 화면 위에서 버튼 낙하 → 밟으면 점프 효과". (GDD §3.4)
6. **트릭 인터페이스 1차 초안** — `activate()` 시그니처 정의. (GDD §8.2)

### Out of Scope (의도적 미포함)
- 트릭 모듈화 (Phase 2)
- 스테이지 전환·저장 시스템 (Phase 3)
- 픽셀 자산 정식 디자인 (Phase 4 — 현재는 placeholder 도형)
- 사운드 (Phase 7)
- UI/메뉴 (Phase 3)

### 합의된 제약 사항
- **GDScript 정적 타입 강제** (GDD §8.5).
- **외피 정체 유지** — 시각은 트롤 플랫포머처럼 보여야 함 (GDD §1.3).
- **무화자 톤** — 텍스트·다이얼로그 금지 (GDD §7.1).
- **무한 리플레이 비목표** — 1회성 발견 경험에 집중 (GDD §2.4).
- **메타 트릭의 OS·하드웨어 종속성 회피** — Phase 1 트릭은 환경 카테고리 (GDD §3.5).

### Phase 1 검증 게이트 (Exit Criteria)
- ✅ 본인 외 1~2명에게 *아무 설명 없이* 플레이시켰을 때 5~15분 내 "아하" 모먼트 발생.
- ✅ 좌절 → 우연 → 아하의 발견 루프 반응이 관측됨 (GDD §2.3).
- ❌ 미충족 시 트릭 디자인 또는 환경 힌팅 수정 (*아키텍처 확장 금지*).
