# Skill: Peer Review (동료 리뷰)
 
## 목적
의사결정이나 설계안에 대해 비판적으로 검토하고 더 나은 대안을 모색합니다.
 
## 실행 시점
- 중요한 기술적 결정을 내리기 전.
- 사용자가 "리뷰해"라고 요청할 때.
 
## 단계별 절차
1. **Context Review**: `requirements/decisions.md` 또는 `architecture/specs/`의 내용을 읽습니다.
2. **Challenge**: 현재 설계의 취약점이나 엣지 케이스를 3가지 이상 도출합니다.
3. **Alternative**: 더 나은 대안(Trade-off 포함)을 제시합니다.
4. **Record**: 논쟁 과정과 결론을 `requirements/debates/` 폴더 내에 기록합니다.
